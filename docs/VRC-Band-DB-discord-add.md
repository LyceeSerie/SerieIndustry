# Discordでの運営登録

## 操作

管理人用チャンネルで `/band-add file:追加バンド.json` を実行し、JSONファイルを添付する。既存コマンドと同じ管理人ロールのみ実行可能。モデレーターは追加できない。

サンプルは `automation/discord/examples/追加バンド.json`。UTF-8のJSON配列に1〜20バンドを記載する。ファイル上限は64KiB。各要素は公開項目の正式名をキー、文字列を値とする。活動名は必須。他の項目は省略可能で、省略は空欄になる。複数回答はカンマ区切り、バンドメンバーは既存フォームと同じ改行・縦棒形式。画像は画像URLを記載し、このコマンドでは画像ファイルをアップロードしない。

使用可能なキーはCore.gsのBandReview.fieldsと一致する27項目：活動名、活動名（よみがな）※ひらがなで入力、活動名（英語）、活動形態１、活動形態２、活動形態３、活動プラットフォーム、メインジャンル、サブジャンル、属性、募集パート、ロゴ、アイコン、アー写、ロゴ配置位置、SNSリンク（X/Twitter）、SNSリンク（Youtube）、VRC Groupリンク、その他SNSリンク1〜5、コメント、活動時間帯、バンドメンバー、YouTube動画URL。項目ごとに4000文字以内、1バンド全体は既存と同じ12000文字以内。

全件を検証してから審査管理シートに保存する。不明なキー、文字列以外の値、活動名なし、上限超過は拒否する。登録ID・登録元・審査状態はシステムが付与する。JSONから指定できない。

追加は承認待ち。既存の通知プログラムが承認／却下ボタン付きメッセージを送り、管理人1人または設定された人数のモデレーターの承認後に公開シートとActionsを経てサイトに反映する。審査を省略して直接公開しない。

既存の `/band-info name:活動名` でIDを調べ、`/band-edit id:登録ID` で編集できる。削除・復元も既存コマンドを使用する。フォームの回答は作成しない。審査・編集・削除時には保持した登録内容を使い、存在しないフォーム回答を読み取らない。

## 登録元と再実行

審査管理レコードにsource=adminと追加者を保持する。公開シート末尾の_registrationSource列にadmin/formを出力し、ビルド時JSONのregistrationSourceへ反映する。詳細ページのバンド名の上に「運営登録」を表示する。既存のフォーム登録は通常表示。編集・削除・復元しても登録元は維持する。旧公開シートはバンドメンバー列・登録元列の既知の追加だけを自動移行する。

同じDiscord操作の通信再試行は、操作IDと配列内の位置で重複作成を防ぐ。途中まで保存された場合も同じ操作の再試行で続きを保存する。別のコマンドで同じファイルを再送すると新規登録になる。同名バンドも許可しているため、失敗表示時はまずband-infoで確認してから再送する。JSONの構文エラーは書き込み前に拒否するが、通信障害時の複数件保存はトランザクションではない。

## 反映手順

1. 変更をfeature/spaへPushし、既存のDiscord配置ActionsでGASとWorkerを更新する。サイトの配置Actionsも完了を確認する。
2. PCで `powershell -NoProfile -File .\automation\discord\local\start.ps1 -RegisterCommands` を一度実行し、band-addを登録する。追加認証や鍵の変更は不要。
3. 管理人用チャンネルでJSONを添付し、通知・承認・公開を確認する。ローカル通知プログラムは稼働が必要。

添付取得は署名検証済みのDiscord操作に限り、HTTPSのcdn.discordapp.com/attachments配下のみ許可。リダイレクトを拒否し、受信中も64KiBを制限する。JSON本体を公開ログへ記録しない。
