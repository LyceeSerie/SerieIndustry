## 入力と表示

イベント名（必須、150文字以内）、形態（必須：VRChat／Cluster／リアル／その他）、場所名・場所リンク（任意）、開始・終了日時（必須、日本時間）、参加バンドを入力する。終了は開始より後とし、日跨ぎに対応する。

参加バンドは登録済みのバンド名・IDを検索して複数選択、または未登録バンド名を自由入力で追加する。登録済みバンドは固定IDで紐付け、同じIDの重複は除く。表示時のバンド名も保持する。検索は最大20候補表示。未登録名はリンクにしない。

通常イベントには登録元のバンドを参加バンドとして含める。運営イベントは登録元を空欄にでき、参加バンドなしでも保存可能。運営イベントへ登録済みバンドを参加者として追加すると、そのバンドページにも表示する。

バンドページは登録元または参加バンドに該当するイベントのうち、終了していないものを開始順に「ライブ予定」として表示する。カードの見た目を維持し、カードをクリックするとイベント詳細へ移動する。カード内の参加バンドリンクは従来通りバンドページへ移動する。

全体カレンダーは日表示・当日・形態全選択・終了イベント非表示が初期状態。日／週／月で表示を切り替える。「終了したイベントも表示」を有効にすると、終了済みも含めて日付と形態で絞り込む。終了済みには終了の表示を添える。表示日・モード・形態・終了イベント設定はURLのday/view/places/endedに保持し、切替・再読み込み・詳細からの復帰で維持する。設定の連続変更でも直前の変更を失わない。

日表示は0:00〜24:00の時間グリッド（1時間72px、30分補助線）。高さ固定の領域内で縦スクロールする。当日には現在時刻の赤線を表示し、初期位置は赤線が見える位置。別の日の初期位置は9時付近とする。利用者がスクロールした後は時刻更新だけで位置を戻さない。時間が重複するイベントは列を分け、日を跨ぐ場合はその日に重なる時間でクリップする。

日表示のスクロールバーは配色共通変数の--db-scrollbar-*で管理する。Chromium／Safari系では幅12px・角丸の背景とつまみ・ホバー色を指定し、Firefox系は標準のscrollbar-width／scrollbar-colorで同じ配色を適用する。スクロールバー領域を確保して内容の幅変動を抑える。強制配色モードではシステムの配色を優先する。

週表示は対象日を含む日曜〜土曜の7列。月表示は月初を含む週の日曜から月末を含む週の土曜まで、7列×4〜6週で表示し、前後月は薄い背景にする。週・月のイベントは開始時刻と名前の簡易表示で、開始順に上から積む。継続イベントは継続と開始時刻を表示する。狭い画面ではカレンダー領域だけ横スクロールし、ページ全体は横へはみ出さない。日付を押すとその日の日表示へ切り替える。

月表示の各日付セルは高さ200pxに固定し、日付見出しを残してイベント一覧部分だけ縦スクロールする。高さは共通テーマの--db-calendar-month-cell-heightで一括変更できる。内部スクロールバーは日表示と同じ共通スタイルを使う。月セルはoverscroll-behavior-y:autoとし、内容が収まっているセルや内部スクロールの端ではホイール操作をページへ引き継ぐ。イベントのある一覧にはキーボードでもフォーカスできる。ブラウザ確認で全セル200px、予定が多い日のみ内部スクロールになり、日付がスクロール領域の外に残ることを確認した。

週・月カレンダーはwheelのcapture段階で横入力を受け、チルトホイールのdeltaXまたはShift＋ホイールを横スクロールへ渡す。内部セルのoverflow領域で横入力が止まるのを防ぐ。通常の縦ホイール、主に縦方向のトラックパッド操作、Ctrl／Meta付きズーム操作は変更しない。line／page単位の入力も換算する。横移動できた時だけ既定動作を抑止し、横幅に余裕がある場合とスクロール端では操作を奪わない。特定のマウス製品には依存しない。

前日／翌日・前週／翌週・前月／翌月、今日、日付選択、形態の複数選択、再読み込みに対応する。月移動時は元の日付を維持し、その日がない場合は月末へ丸める。該当なし・取得中・取得失敗を区別して表示する。

日付の自由入力と「表示日」の可視ラベルは廃止する。日表示は年／月／日、週表示は年／月とN週目、月表示は年／月のプルダウンとする。前後移動・今日・選択欄はいずれも高さ40pxで中央を揃える。各選択欄には年・月・日・週のアクセシブル名を付ける。

週番号は、選択した月の1日を含む日曜始まりの週を1週目とする。週の代表日は選択月内に置き、例えば2026/12の1週目は11/29〜12/5を表示しつつ選択欄は2026/12・1週目を維持する。月ごとに4〜6週の選択肢を生成する。日・週が存在しない年月へ変更した場合は末日・最終週へ丸める。年の候補は今年の前後10年と現在選択中の年。

終了判定は終了日時 <= 現在時刻。1秒ごとと画面復帰時に再評価し、カレンダーの初期状態・バンドページ・登録画面一覧から終了済みを除外する。保存データ自体は消さない。登録画面で表示中の入力は自動破棄しない。

イベント詳細URLは `/#/VRCBandDB/events/:eventId`。イベント名、形態、場所名、開始・終了日時、参加バンドを表示する。カレンダーで終了表示を有効にして開いた詳細は終了済みも表示し、終了を明記する。それ以外の終了済み詳細は終了の案内だけを表示する。削除・存在しないIDは見つからない案内とする。いずれもカレンダーへ戻れる。本番フラグと読取元はカレンダーと共通。

日表示の対象は開始日時が翌日0時より前、かつ終了日時が当日0時より後のイベント。翌日0時ちょうどに終了したイベントは翌日に含めない。時刻は保存時にタイムゾーン付きISOへ正規化し、表示は日本時間に統一する。

## 認証・保存と公開

登録画面はWorkerのGET /api/events、POST /api/events/save、POST /api/events/deleteを利用する。既存のDiscordセッション・同意・CSRF検証を適用し、WorkerからGASへ署名付きで操作を送る。一般ユーザーは現在所有しているバンドのイベントだけを登録・編集・削除できる。所有権移譲後は以前の所有者の操作を拒否する。運営単独イベントと全件操作は管理人に限定する。クライアントの管理人フラグやactorIdは信用しない。

登録済み参加バンドは存在を検証し、バンド名をサーバー側で補正する。一般ユーザーの候補一覧は承認済みバンドと本人所有のバンドに限定する。他人の未公開バンドは含めない。

非公開の審査用スプレッドシートにLiveEventsタブを作り、イベント本体・削除状態・作成者・操作者・更新番号・再送識別情報を保持する。公開Eventsタブには上記12列だけを書き出す。ブラウザからGoogle Sheetへ直接書き込まない。公開側を手編集しても次回保存時に非公開記録から再生成されるため、編集は登録画面を利用する。

保存・削除はUUIDのrequestIdで再送を識別する。同じ操作の再送ではイベントや更新番号を増やさない。古いrevisionはSTALE_EVENTとして拒否し、再読み込みを案内する。公開書込に失敗しても同じ内容を再送して復旧できる。操作は1ユーザー1日100回まで。削除は非公開側に記録を残し、公開側から除去する。イベント操作ではDiscord通知やGitHub Actionsは起動しない。

GAS設定の既定値はEVENT_SPREADSHEET_ID=上記ID、EVENT_SHEET_ID=0、EVENTS_ENABLED=true。既定値のままなら追加のスクリプトプロパティ入力は不要。審査用・バンド公開用シートとの混用は拒否する。GAS実行アカウントには編集権限、公開シートは一般閲覧権限が必要。

読取は公開CSVをcache:no-store／credentials:omitで取得する。Google側の配信キャッシュによる反映遅延はあり得る。登録画面は保存APIの応答を直ちに一覧へ反映する。画面を公開するにはGAS・Workerの配置に加え、静的サイトの通常デプロイが必要。
