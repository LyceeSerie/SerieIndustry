## 権限

| 分類 | ロールID | 実行可能な操作 |
| --- | --- | --- |
| 管理人 | 1572585514404413511 | 1人で承認/却下の確定、登録状態の確認、掲載削除 |
| モデレーター | 1572821971165646938 | 承認票・却下票の投票。既定では同じ結論が3人分集まると確定 |
| その他 | — | 審査・管理コマンドを実行不可 |

- 通知・審査チャンネル：1572258078017986620。
- 管理人用コマンドチャンネル：1572821384353288252。
- 両方のロールを持つ人は管理人として扱う。
- Discordの実際の署名付きInteractionに含まれるロールからWorkerが分類し、HMAC署名したactorRoleをGASへ送る。コマンド引数やボタンから分類を指定できない。
- GASは署名を検証した後で役割を確認する。ローカル通知専用鍵では承認・削除を実行できない。
- Workerの旧ALLOWED_ROLE_IDSは使わず、ADMIN_ROLE_IDSとMODERATOR_ROLE_IDSへ分離した。

## 票の数え方

承認票と却下票は別に集計し、同じDiscordユーザーIDは1票。確定前は同じ人が承認/却下を押し直して投票先を変更できる。単なる押し直しでは票を増やさない。古いInteractionの再試行で後の投票を巻き戻さない。

既定では、承認3票でapproved、却下3票でrejected。管理人は1票で指定した結論を確定する。承認が確定した時だけ公開コピーの更新とActions起動を予約する。未確定の票ではサイト更新を起動しない。却下では前回承認済みの公開内容を維持する。

GASロックで票の更新と確定を直列化する。先に確定した結論を後のクリックで上書きしない。回答編集で新しい版になったら投票をリセットし、前回承認済みデータは再承認まで維持する。既存の確定済み審査を新ルールでやり直したり、掲載を自動停止したりはしない。

通知には投票数と必要人数を表示する。投票の現状はRegistrationsのrecordJson.votes、投票履歴は新しいReviewVotesタブ、審査版と状態の履歴はAuditへ保存する。ReviewVotesは既存の審査管理用シートに自動作成し、公開用シートには出さない。永続化リトライにより履歴行が重複する場合はinteractionIdで識別する。

## 人数を変える方法

GASの「プロジェクトの設定 → スクリプトプロパティ」で設定する。

| プロパティ | 既定値 | 用途 |
| --- | --- | --- |
| MODERATOR_VOTE_THRESHOLD | 3 | 共通の必要人数 |
| MODERATOR_APPROVE_THRESHOLD | 未設定/空欄 | 承認だけを変える場合の上書き。未指定なら共通値を使う |
| MODERATOR_REJECT_THRESHOLD | 未設定/空欄 | 却下だけを変える場合の上書き。未指定なら共通値を使う |

例：共通5、承認・却下は空欄 → 両方5人。共通5、承認は空欄、却下2 → 承認5人・却下2人。上書き設定を削除または空欄へ戻すと共通値へ連動する。

有効値は1〜99の整数。共通値のコード上の既定はCore.gsのdefaultVoteThresholdだけで定義し、GAS設定・通知の既定も参照する。変更のためにソースの変更・GAS関数の手動実行・本番再配置は不要。次のGAS処理で反映する。

未確定の投票は人数変更後も保持する。通知の分母は次の取り込み・通知取得処理で更新する。必要人数を下げてもそれだけで自動確定せず、次の承認/却下操作でその結論の票数を判定する。既に確定した審査には遡及適用しない。

## 管理人用コマンド

専用チャンネルで使用する。

```text
/band-info id:通知に表示された登録ID
/band-info name:活動名
/band-info name:活動名 page:2
/band-delete id:通知に表示された登録ID
```

- band-info：idまたはnameのどちらか一方で検索する。名前は部分一致（NFKC正規化・英字の大文字小文字を区別しない）で検索し、同名の登録もまとめず、各登録の活動名・登録ID・版・審査状態・掲載の有無を表示する。掲載削除済みの履歴も検索対象。
- 検索結果は1ページ5件。総件数とページ数を表示し、6件以上は同じnameにpage:2等を付けて全件確認する。範囲外・該当なしはその旨を表示。id検索ではUUIDの大文字小文字を区別しない。検索による審査・公開状態の変更やActions起動は行わない。
- 削除は検索結果の登録IDをband-deleteへ渡す。band-deleteは名前を受け付けず、同名登録を一括削除しない。nameとidの同時指定、pageだけの指定は拒否する。
- band-delete：対象名・登録ID・版を本人だけに表示し、「掲載削除を確定」ボタンを出す。この段階では削除しない。
- 確定ボタンは5分間有効。発行した管理人・サーバー・専用チャンネル・登録ID・版にHMACで結び付ける。別の管理人やモデレーターへの転送・別の登録への差し替え・期限切れ・回答編集後の古い確認は拒否する。
- 確定時に改めて管理人ロールをチェックする。確認後にロールを失った場合も実行できない。
- 掲載削除はstatus=deletedとし、公開済みスナップショットを除いて、公開シート再生成とActionsを予約する。元フォーム回答、審査用レコード、監査履歴は残す。
- 削除した同じフォーム回答を編集しても自動復活させない。復元コマンドは今回含めない。
- 既存の通知は削除済み表示へ更新し、承認・却下ボタンを無効にする。Discord上のメッセージそのものは削除しない。
- サイト反映完了はActionsの結果とサイトで確認する。コマンドの成功応答を公開完了と扱わない。

## 初回反映・登録手順

1. 今回の変更をfeature/spaへPush。Deploy Discord integrationでGASとWorkerの両方の更新成功を確認する。
2. 専用チャンネルでBotが使えることを確認し、管理人に「アプリコマンドを使う」権限を許可する。
3. ローカルPCのチェックアウトも今回の変更が入った状態で、保存済みのBot Tokenを使い以下を1回実行する。

```powershell
cd C:\Users\Cubase\Documents\SerieIndustry
powershell -NoProfile -File .\automation\discord\local\start.ps1 -RegisterCommands
```

現在のBotが一致することを確認後、対象サーバーにband-info/band-deleteの2件を登録する。再実行は名前で更新し、他のコマンドを一括削除しない。完了すると終了し、通常の通知プログラムを追加起動しない。既に動いている通知プログラムを止める必要もない。

名前検索追加後はGAS・Workerを配置し、上記のRegisterCommandsを再度実行する。これによりDiscordの入力欄へname/pageが追加される。保存済みの認証情報を使い、追加のToken設定は不要。

スラッシュコマンド自体はクライアントに表示される場合があるが、Workerは管理人ロール・専用チャンネル以外を必ず拒否する。表示も制限したい場合は、Discordサーバー設定の連携サービスで対象アプリのコマンド利用者を管理人ロールに限定する。一般のDiscord管理権限があっても、指定の管理人ロールを持たない人はこの実装では実行できない。

ロールIDと専用チャンネルIDは今回の値をWorker設定とGASの既定値へ反映済み。追加のGitHub Secret、Cloudflare Secret、GAS_HMAC_SECRETやLOCAL_NOTIFY_SECRETの再生成は不要。

専用チャンネルを後から変える場合は、worker/wrangler.jsoncのDISCORD_COMMAND_CHANNEL_IDとGASスクリプトプロパティの同名設定を揃えて変更する。ロールIDはworker/wrangler.jsoncのADMIN_ROLE_IDS/MODERATOR_ROLE_IDSを変更する（複数はカンマ区切り）。ロール・Worker変数の更新は配置が必要。必要人数はGASプロパティだけで変更できる。

GAS→Workerは順次配置のため、更新途中は新旧のAPIが一致せず操作を拒否する時間があり得る。両方の更新完了後に操作する。
