# 管理人による応急編集

更新：2026-11-19。実装・ローカルテスト済み。本番配置・コマンド再登録・実Discordでの操作確認は未実施。

## 使い方

管理人用チャンネル（1572821384353288252）で実行する。

```text
/band-edit id:登録ID
```

1. 項目名のプルダウンから編集対象を1つ選ぶ。
2. 現在値を確認し、「内容を編集」を押す。
3. 現在値が入った入力画面で内容を書き換えて送信する。

管理人ロール（1572585514404413511）専用。モデレーターからは操作できない。登録IDはband-infoの名前検索でも確認できる。

## 編集範囲

公開用項目26件（活動名・活動形態・ジャンル・属性・募集パート・画像URL・SNSリンク・コメント・活動時間帯・バンドメンバー等）を選択できる。登録ID、版、審査状態、投票、メールアドレス、秘密情報などの管理項目は選択できない。画像項目はURLの編集で、Discordからの画像アップロードは行わない。

1項目最大4000文字、登録全体は既存のJSON換算12000文字まで。現在値が4000文字を超える場合はフォーム編集を案内し、値を途中で切って保存しない。空欄は項目のクリアとして扱うが、活動名は空欄にできない。複数選択項目も文字列として編集し、カンマ区切り等の既存のサイト取り込みルールを使う。

## フォームとの関係

Googleフォームの回答や回答先シートを直接書き換える機能ではない。応急編集は審査レコードのadminOverridesに保存する。

- フォームの当該項目が同じ値の間は、定期取り込みでも応急編集を維持する。
- 利用者がフォームで同じ項目の値を変更すると、その項目の応急編集を解除してフォーム側を優先する。
- ほかの項目だけの変更では、当該項目の応急編集は維持する。
- 利用者の修正値が応急編集の値と同じでも、上書きの解除を保存する。その後にフォームを元の値へ戻しても古い応急編集を再適用しない。
- フォームの同じ値を再送信しただけでは解除しない。比較はフォーム取り込みで整形された項目値に対して行う。

band-infoには応急編集の有無も表示する。原則は利用者にフォームを編集してもらい、このコマンドは緊急対応に使う。

## 掲載と審査

- 承認済みの掲載データがある場合、管理人が選んだ項目だけを承認済みスナップショットへ反映して、サイト更新を予約する。
- ほかの未承認変更は公開しない。最新回答が既存の公開内容と異なる部分は引き続き承認待ちとする。
- 未承認の登録は編集しても自動掲載せず、承認待ちにする。
- 編集で版を進め、票をリセットする。古い通知・編集画面からの上書きは拒否する。
- 保存後、Discord通知はGitHub ActionsがGASの通知キューを取得して更新する。公開処理の完了はGitHub Actionsとサイトで確認する。
- 掲載削除済みの登録は編集不可。必要なら管理人がband-restoreで復元してから編集する。

## 権限・確認・履歴

項目選択・入力画面には5分の期限がある。登録ID、版、本人、サーバー、チャンネル、対象項目を署名で検証する。別ユーザー・別項目への流用、期限切れ、フォーム変更後の古い入力は保存しない。送信時にも管理人ロールを確認する。ローカル通知用の鍵では編集できない。

項目選択後はGASから現在値を取得する。入力画面を開く操作はWorkerが署名を検証し、外部通信せずに即座にModalを返す。Discordの初回応答期限内にGASへの読取を待たず、現在値も省略しないために「内容を編集」ボタンを挟む。

同じ入力画面の同じ内容の再送信は、保存済みとして扱い版・履歴・公開キューを増やさない。異なる内容での古い画面の再送信は拒否する。

AdminEditsタブを審査用シートに自動作成し、日時、登録ID、編集前後の版、項目名、編集前後の値、操作者ID、Interaction IDを記録する。審査用の非公開シートで保持し、公開用シートには出さない。記録と登録保存の途中で通信が失敗した場合、履歴が重複することがあるためInteraction IDで識別する。

## 反映手順

1. 変更をfeature/spaへPushし、GASとWorkerの更新成功を確認する。
2. PCのコードも更新された状態で、保存済み認証情報を使いコマンドを再登録する。

```powershell
powershell -NoProfile -File .\automation\discord\local\start.ps1 -RegisterCommands
```

既存の通知プログラムの停止・鍵の再設定は不要。新しいコマンドはband-edit。登録処理はband-info/band-delete/band-restoreを維持し、無関係のコマンドを一括削除しない。
